# Prompts

**For Gerson:** paste the whole file as the system prompt of the Anthropic Claude module, send the inputs as a JSON string in the user message, and set temperature to 0.2. Follow each Claude module with a Parse JSON module. Every prompt replies with JSON only.

**01_propose_role_split.md** is used by the scenario "Scout 1: Role documents and expected splits", once for each role document read from Google Drive. In: `role_title`, `job_description` (the document's text) and `kpis` (its performance measures). Out: `{ topics: [{ name, description, proposed_percent, reasoning }] }`, five or six topics whose whole number percents add up to 100, including exactly one "Internal meetings and administration" topic between 5 and 15. The scenario still checks the sum and adjusts the largest topic if needed.

**02_interview_turn.md** is used by the scenario "Scout 4: Interview turn", once per turn, and must answer within the 12 second limit (max tokens 600). In: `person_name`, `role_title`, `topics` (approved), `day`, `working_minutes`, `calendar_activities`, `transcript_activities` and `turns_so_far` (empty on the first call). Out: `{ done, question, kind, evidence }`. When `done` is true, `kind` is `closing`, `evidence` is an empty string and the scenario starts the day summary. The scenario's own six question limit still applies as a safety net.

**03_day_summary.md** is used by the scenario "Scout 5: Day summary", started by the interview scenario when the interview is done. In: the same inputs as the interview, with the full `interview` in place of `turns_so_far`, plus `known_outside_labels` (the outside role labels already used in the company). Out: `{ allocations: [{ topic_name, label, in_role, minutes, evidence }], summary_text }`, with minutes in multiples of 5 adding up to `working_minutes`. The scenario computes each `percent`, maps `topic_name` to `topic_id`, and adjusts the largest row if the total is slightly off.

**04_suggest_workflows.md** is used by the scenario "Scout 7: Suggest workflows". In: `period_start`, `period_end`, `working_days_in_period`, `team_history` (approved minutes rolled up per person and label, with minutes by weekday and a few sample evidence lines), `people` (with hourly cost) and `roles_and_topics`. Out: `{ candidates: [...] }`, at most four, each with the four scores from 1 to 5, the reasoning and three to six `proposed_steps`. The model never gives `total_score`, `rank` or `annual_cost_eur`: the scenario computes them with the formula in the shared rules.

**05_draft_workflow_fill.md** is used by the scenario "Scout 8: Decision and draft creation", after a manager approves a candidate. In: the approved `candidate`, the `template_description` of the hand built template, and `contacts` (name and email of each person affected). Out: `{ scenario_name, schedule: { day, time }, source_sheet_name, recipients, summary_prompt }`, the values that fill the template's placeholders before the draft is created through the make.com API.
